# Implementation Plan

実装は上から順に行う。並列マークは付けない。各サブタスクは 1〜3 時間を目安とする。

- [ ] 1. 視覚基盤とシェル
- [x] 1.1 暗いガラス調の色と余白を全体に適用し、OS の明るい外観へ切り替えない
  - 別紙6-4のトークンを正本として読み込み、既存の白背景・自動 Light 切替を外す
  - 日本語本文フォントを Noto Sans JP（700 以上は使わない）にする
  - ブラウザで初期表示が near-black のグラデーション背景になり、OS を Light にしても白基調に戻らない
  - _Requirements: 2.1, 11.3, 11.5_

- [x] 1.2 カード・入力・主操作・送信の基本部品をトークンどおりに揃える
  - ベージュの主操作は高さ 48px、角丸 12px。送信円は sage で主操作と別物に見える
  - 失敗表示は低彩度の注意と再試行に留め、真っ赤な全面パネルは置かない
  - 絵文字・カラフルアイコン・ネオンは primitive に含めない
  - 単体の確認画面で主操作が1つ、送信が別形状として見える
  - _Requirements: 2.2, 2.3, 2.6, 11.2_

- [x] 1.3 画面種別に応じてヘッダー／サイドバー有無を切り替え、コアの再訪入口だけ出す
  - ログインはシェルなし中央カラム、初回同意はヘッダーのみ、相談以降は標準シェル
  - コアのサイドバーは「新しい相談」「進行中の相談」「振り返り」のみ。履歴等は出さない
  - 押せないプレースホルダ項目は置かない
  - `/login` でシェルなし、仮の同意後画面で標準シェルと3項目ナビが見える
  - _Requirements: 3.1, 3.2, 3.3, 3.4_

- [ ] 1.4 相談から振り返りまでのステップ表示を置き、未到達の未来へ飛ばせないようにする
  - ラベルは「相談 → 整理 → 仮説 → 打ち手 → 実行 → 振り返り」
  - ログインと同意ではステップ表示を出さない
  - 未来ステップをクリックしても現在地が変わらない
  - _Requirements: 3.5, 3.6, 3.7_

- [ ] 1.5 検証用の状態土台を置き、入口をログインにしてホームを作らない
  - 同意・セッション・スコープ初期値 core を持つモック状態をルートから読めるようにする
  - ルート `/` はログインへ送る。ダッシュボードは置かない
  - 新しい画面番号を利用者向け UI に出さない
  - `/` を開くとログインに着き、ホームという名の画面が存在しない
  - _Requirements: 1.2, 1.4, 1.5_

- [ ] 2. ログイン・同意・相談開始
- [ ] 2.1 仮のログイン画面を置き、サービス名と第三者性の仮コピーを出す
  - サービス名は「伴走」（仮）。メール＋パスワードはモック用仮置きと分かる注記を置く
  - 主操作は「ログイン」1つ。未同意なら同意へ、同意済みなら相談入力へ進む
  - ログイン画面にシェルがなく、仮置き注記が見える
  - _Requirements: 1.3, 2.7, 4.1, 4.2, 4.3_

- [ ] 2.2 必須3項目の同意画面を置き、未完了では先へ進めない
  - 必須3項目が揃うまで「同意して進む」を押せない。理由を短く出す
  - 同意完了後は相談入力へ進む
  - 初回はヘッダーのみで、未チェック時に主操作が非活性である
  - _Requirements: 3.2, 4.4, 4.5_

- [ ] 2.3 自由記述の相談入力から対話を開始できるようにする
  - 構造化フォームや 5W3H ラベルは出さない。MOCK-DEC-01 の仮コピーを使う
  - 開始成功でコーチング対話へ進む。失敗時は入力が残る（失敗の見た目は Wave 6 で完成してよい）
  - 機密候補 Variant 用の伏せ確認枠を置ける構造にする
  - 相談を書いて開始すると対話画面に遷移し、課題構造化の入力欄がない
  - _Requirements: 2.4, 4.6, 4.7, 4.8, 4.9_

- [ ] 3. コーチング対話のコンテナと台本
- [ ] 3.1 あらかじめ書いた台本で次の問いを返し、外部の生成AIは呼ばない
  - 次ターン取得に短い待ちを入れ、「考えています」を出せる
  - 失敗時は再試行可能なエラーを返し、入力は消さない
  - ネットワーク先の生成AIに接続する経路がない
  - _Requirements: 1.1, 1.2, 5.4, 5.5_

- [ ] 3.2 一つの対話画面で左右の吹き出しと下部入力を固定表示する
  - AI 左・利用者右。1吹き出し1問。入力は下部固定
  - 送信は sage 円で、画面のベージュ主操作とは別物
  - 直近の問いと入力欄が常に見える
  - `/consult/[sessionId]` 相当の一つの画面だけで会話が進む
  - _Requirements: 2.3, 5.2, 5.3_

- [ ] 3.3 中断再開と、閉じられる関連知識カードを対話内に置く
  - 「保存して、あとで続ける」で進行中として再開できる
  - 関連知識は独立画面にせず、対話内の閉じられるカードにする
  - 中断後に「進行中の相談」から同じ会話に戻れる
  - _Requirements: 5.6, 5.7_

- [ ] 4. 整理・仮説・打ち手・次アクションを同一画面内に実装する
- [ ] 4.1 整理ステップで事実／受け止め方／感情／困りごとを確認する
  - 主操作は「この整理で先へ進む」1つ。修正は対話へ戻し、会話は消さない
  - コアでは任意出口を改善事例詳細へ向ける（一覧は出さない）
  - 同じ対話 URL のまま整理カードが見える
  - _Requirements: 5.1, 6.1, 6.2, 6.3_

- [ ] 4.2 仮説ステップで複数仮説を示し、原因を一つに決めない
  - 各カードに仮説・根拠・まだ分からないことを載せる
  - 断定コピー（「原因はこれです」）を出さない
  - 仮説が3件並び、同一画面のまま打ち手へ進める
  - _Requirements: 2.5, 6.4_

- [ ] 4.3 打ち手ステップで候補から1件選ぶまで確定できないようにする
  - 候補は複数。コアでは経験者 Advice への導線を出さない
  - 選択後にだけ「この案を次の一歩にする」が押せる
  - 未選択では主操作が非活性である
  - _Requirements: 6.5, 6.6_

- [ ] 4.4 次アクション確認で試す内容を確定し、現場実行の画面は作らない
  - いつ・どの場面・何をするかを確認する。「対象」は空でも確定できる
  - 具体化不足では確定できない。成功後はあとで振り返れる旨だけ示す
  - 実行専用の画面ルートが存在しない
  - _Requirements: 6.7, 6.8, 6.9, 11.1_

- [ ] 4.5 内包ステップの行き来で会話が消えず、独立ページに分裂しないことをつなぐ
  - 整理／仮説／打ち手／確認の戻りで履歴が残る
  - ブラウザの場所は対話の一つの画面のままである
  - ステップを戻しても直近の問いと入力欄が見える
  - _Requirements: 5.1, 6.10_

- [ ] 5. 改善事例と振り返り
- [ ] 5.1 改善事例詳細を対話の外の画面として出し、正解ではない注意を置く
  - 「原因の仮説を考える」で仮説ステップへ、「整理に戻る」で整理へ戻る
  - 取得失敗では対話または整理へ戻れる
  - 事例画面に対話シェル内埋め込みではなく別画面として注意文が見える
  - _Requirements: 7.1, 7.2, 7.3, 7.4, 7.5_

- [ ] 5.2 振り返り開始で実施有無を採点せずに入力できるようにする
  - 「試した / 一部できた / 今回はできなかった」を選べ、未実施でも開始できる
  - 採点UIではない旨の仮コピーを出す
  - 未実施を選んでも「振り返りを始める」が使える
  - _Requirements: 8.1, 8.2, 8.3_

- [ ] 5.3 振り返り対話をコーチングと同じ系統で進め、次アクション確認へ戻す
  - 人間同士チャットと同じ見た目にはしない。コアでは個人攻略法へ出さない
  - 学び確認後に次の一歩を決めると確認ステップへ戻る
  - 振り返りから次アクション確認に戻り、実行画面は開かない
  - _Requirements: 8.4, 8.5, 8.6, 8.7_

- [ ] 5.4 サイドバーの進行中と振り返りから正しい再開位置へつなぐ
  - 進行中は相談の再開位置、実行待ち／振り返り待ちは振り返り開始へ
  - 「新しい相談」は相談入力へ
  - コア一周のあと、ナビだけで再開と振り返りに入れる
  - _Requirements: 3.8, 3.9, 3.10_

- [ ] 6. 検証者向け切替と必須状態
- [ ] 6.1 相談UIの外にシナリオ切替を置き、初回／同意済み／進行中／実行待ち／振り返り待ちを再現する
  - パネルは「検証用」と分かり、ベージュの大型主操作にはしない
  - 切替後に該当の前提画面が開く
  - 利用者向けナビの中に切替が混ざっていない
  - _Requirements: 9.1, 9.2, 9.5_

- [ ] 6.2 コア画面の必須 Variant を切替で表示する
  - MOCK-DEC-01 の未認証失敗、同意非活性、機密検知、生成失敗、事例失敗、振り返り失敗などを選べる
  - 選んだ状態が対象画面に実際に見える
  - _Requirements: 2.6, 4.3, 4.7, 4.9, 5.5, 7.5, 8.7, 9.3_

- [ ] 6.3 拡張スコープの切替口を検証パネルに用意し、初期はコアのままにする
  - 初期は拡張ナビが出ない。パネルから extended にしたときだけ後続画面用の入口が有効になる準備ができる
  - コアのまま起動すると履歴・攻略法・成長・匿名交流が見えない
  - _Requirements: 3.4, 9.4, 10.1_

- [ ] 7. 拡張画面
- [ ] 7.1 類似事例一覧を正規経路にし、整理からの任意出口を一覧経由にする
  - 件数は3。類似スコア数値は出さない。空／失敗 Variant を切替できる
  - 一覧から事例詳細、スキップで仮説、副操作で統計へ進める
  - extended 時、整理の任意導線が一覧を開き、コア時の直通 008 に戻さない
  - _Requirements: 6.3, 10.1, 10.2, 10.3_

- [ ] 7.2 本音統計と適応プロセスを事例の枝として置く
  - 統計に能力評価ではない注意と母集団・件数を出し、グラフとベージュ主操作は置かない
  - 適応は「必ず慣れる」ではない注意付きタイムライン。008 には埋め込まない
  - 統計・適応から一覧または対話へ戻れる
  - _Requirements: 10.2, 10.3_

- [ ] 7.3 経験者 Advice を打ち手から開き、常時「正解ではない」と戻れる
  - 所属企業名は出さない。遷移元（打ち手または一覧）へ戻る
  - 参考になったボタンは置かない
  - 打ち手から Advice を開き、注意が常時見える
  - _Requirements: 6.6, 10.4_

- [ ] 7.4 個人攻略法・履歴・成長を診断やスコアなしでつなぐ
  - 攻略法は性格診断ではない。データ不足なら傾向を出さない
  - 履歴は吹き出し羅列にせず、振り返り待ちの行だけ開始主操作を持つ
  - 成長に総合スコア・偏差値・ランクを出さない。根拠は履歴へ
  - 振り返りから攻略法へ入り、履歴と成長を行き来できる
  - _Requirements: 8.6, 10.3, 10.5, 10.6_

- [ ] 7.5 匿名マッチングと人間同士チャットを任意機能として置く
  - 双方同意前はメッセージを始めない。マッチ度スコアは出さない
  - チャット見た目はコーチング対話と区別し、sage 送信円は使わない
  - 同意前は送信できず、同意後だけ会話画面が開く
  - _Requirements: 8.4, 10.7_

- [ ] 7.6 監査画面を利用者シェルなしで置き、相談本文を出さない
  - 別ヘッダー。会話UI・Stepper・相談用ベージュ CTA は置かない
  - 権限不足では内容を出さない。本文・チャット全文のダミーも置かない
  - `/admin` 相当で利用者ナビが出ず、本文列が存在しない
  - _Requirements: 10.8, 10.9, 11.4_

- [ ] 8. 通し検証
- [ ] 8.1 コア導線をブラウザで一周し、禁止UIが混ざっていないことを確認する
  - 001→002→003→004内ステップ→任意008→014→015→013 をクリックだけで辿れる
  - 各画面／ステップのベージュ主操作が1つ。断定コピーと 5W3H ラベルがない
  - 実行専用画面とホームがなく、新しい SCR 番号も増えていない
  - _Requirements: 1.1, 1.4, 1.5, 2.2, 2.4, 2.5, 11.1, 11.2, 11.3_

- [ ]* 8.2 未来ステップへ進めないことと、確定後に実行画面が無いことを自動テストで固定する
  - 要件 3.7 と 6.9 / 11.1 の受け入れを、実装後でも再実行できるテストにする
  - コア実装が既に手動確認済みなら後回しにしてよい
  - _Requirements: 3.7, 6.9, 11.1_
