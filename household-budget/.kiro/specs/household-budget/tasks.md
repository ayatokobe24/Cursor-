# Implementation Plan

- [x] 1. 基盤: クライアント導入と共有の結果表現
- [x] 1.1 公式クライアントを導入し公開設定だけをアプリが読む
  - ブラウザに載せてよい接続先と公開キーのみを使い、サービスロールは置かない
  - パスワードや管理トークンをリポジトリとバンドルに含めない
  - 開発起動時に公開設定が無いと認証クライアントを作れないことが分かる
  - _Requirements: 1.6_

- [x] 1.2 成功失敗の結果型と家計・セッションの共有概念を揃える
  - 記録は種別・正の整数円・暦日・任意メモ・所有者を表す
  - セッション利用者は Auth の利用者識別子とメールだけを持ち、資格情報は含めない
  - 後続の検証・永続化・画面が同じ語彙でやりとりできる
  - _Requirements: 1.6, 1.7, 2.1, 2.6_

- [x] 2. ドメイン: 円・暦月・下書き検証・月次要約
- [x] 2.1 (P) 金額を日本円の整数として表示する
  - 一覧と要約で同じ通貨表示になる
  - 純関数の単体テストが通る
  - _Requirements: 2.6, 3.5, 4.5_
  - _Boundary: MoneyFormat_
  - _Depends: 1.2_

- [x] 2.2 (P) 暦月を半開区間に変換し初回対象月を決める
  - 対象月の開始日と翌月開始日が取れ、不正な月指定は当月に倒せる
  - 純関数の単体テストが通る
  - _Requirements: 4.2, 4.4_
  - _Boundary: MonthRange_
  - _Depends: 1.2_

- [x] 2.3 (P) 記録下書きを検証する
  - 種別または発生日の欠落、金額の未入力・0以下・非整数では保存せずフィールド誤りになる
  - 空メモは無いものとして扱い、整数円は受け入れる
  - 純関数の単体テストが通る
  - _Requirements: 2.1, 2.3, 2.4, 2.6_
  - _Boundary: TransactionValidation_
  - _Depends: 1.2_

- [x] 2.4 (P) 対象月の行から収入合計・支出合計・差引を出す
  - 差引は収入合計から支出合計を引いた値で、0件ならいずれも0円
  - 一覧に渡す行集合と同じ入力から要約が出る
  - 純関数の単体テストが通る
  - _Requirements: 4.1, 4.3, 4.5_
  - _Boundary: MonthSummary_
  - _Depends: 1.2_

- [x] 3. 認証基盤: セッション Cookie と本人確認
- [x] 3.1 ブラウザ用とサーバー用のセッション対応クライアントを用意する
  - Cookie 経由で Auth セッションを読み書きできる
  - サーバー検証はセッションの存在確認だけでなく利用者の確定に使う
  - _Requirements: 1.6, 1.7_
  - _Boundary: SupabaseAuth_

- [x] 3.2 サーバーで現在利用者を確定する
  - 確定できないときは家計の読取・変更を続けない
  - 戻りにパスワードや更新トークンを含めない
  - 未確立時に家計データが出ない
  - _Requirements: 1.5, 1.7, 1.8_
  - _Boundary: AuthSession_
  - _Depends: 3.1_

- [x] 3.3 リクエストごとにセッションを更新し未認証を認証へ送る
  - 家計画面は未認証なら認証を求め記録内容を出さない
  - 認証済みが認証画面を開くと家計へ戻る
  - 応答からセッション Cookie を落とさない
  - _Requirements: 1.4, 1.5, 6.2_
  - _Boundary: AuthProxy_
  - _Depends: 3.1_

- [x] 3.4 メールとパスワードで登録・ログイン・ログアウトする
  - 登録またはログイン成功でセッションを Cookie に残し家計へ進める
  - 誤った認証情報では家計へ進めず誤りを示す
  - セッションが立たない登録（確認待ちを含む）では家計を出さず失敗を示す
  - ログアウト後は家計へ進めない
  - パスワードをアプリ側ストアに保存しない
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.6, 1.8_
  - _Boundary: AuthService_
  - _Depends: 3.1, 3.2_

- [x] 4. 認証画面と確認メール後の復帰
- [x] 4.1 登録とログインの画面を出す
  - メールとパスワード以外の本人確認手段を出さない
  - 失敗時に家計データを出さない
  - 利用者が登録・ログイン操作を完了できる
  - _Requirements: 1.1, 1.2, 1.3, 1.8_
  - _Boundary: AuthPages_
  - _Depends: 3.4_

- [x] 4.2 確認メール等のコードをセッションに交換する
  - 交換成功で家計へ進み、失敗では家計データを返さない
  - 一般の記録 API は追加しない
  - _Requirements: 1.1, 1.7, 1.8_
  - _Boundary: AuthCallback_
  - _Depends: 3.1_

- [x] 5. 記録の永続化
- [x] 5.1 自分の取引だけを月単位で読み書きする
  - 発生日は設計どおりの暦日列を使い、カテゴリは参照しない
  - 他利用者の行は一覧に出ず、見えない更新はなかったことになる
  - 共有用の列や招待手段を追加しない
  - 取得・保存失敗は呼び出し元が失敗として扱える
  - _Requirements: 2.1, 2.2, 3.1, 5.1, 5.2, 5.4, 6.1, 6.3, 6.4_
  - _Boundary: TransactionRepository_

- [x] 5.2 検証済みの下書きだけを自分の記録として追加・更新・削除する
  - セッション利用者以外の所有者をクライアント入力で付け替えない
  - 削除は確認があるときだけ行い、未確認なら記録が残る
  - 成功後に家計画面が最新の一覧と要約を読める
  - 未ログインの変更は認証エラーになる
  - _Requirements: 2.1, 2.2, 2.5, 5.1, 5.2, 5.3, 5.4, 6.3_
  - _Boundary: TransactionActions_
  - _Depends: 3.2, 2.3, 5.1_

- [x] 6. 家計画面
- [x] 6.1 対象月の行を読み要約と一緒に返す
  - 月未指定なら開いた時点の暦月
  - 0件でも要約は0円
  - 呼び出し前に利用者が確定している
  - _Requirements: 3.1, 4.1, 4.3, 4.4_
  - _Boundary: LedgerLoader_
  - _Depends: 2.2, 2.4, 5.1, 3.2_

- [x] 6.2 要約・追加操作・明細の順で家計ホームを組む
  - テンプレート由来の導入・デプロイ案内を主内容に出さない
  - 記録の追加が画面の主アクションとして1つ分かる
  - 認証済みだけがこの画面を見る
  - _Requirements: 7.1, 7.3, 7.5, 1.5_
  - _Depends: 6.1_

- [x] 6.3 明細に種別文言・金額・発生日・メモを出し空なら記録へ誘導する
  - 収入と支出を色だけに頼らず文言でも区別する
  - 金額は円として読める
  - 対象期間に0件ならその旨と次操作が分かる
  - _Requirements: 3.2, 3.3, 3.4, 3.5_
  - _Depends: 6.1, 2.1_

- [x] 6.4 記録フォームにラベルを付け、保存中は同じ保存を受け付けない
  - 種別・金額・発生日・任意メモを保存できる
  - 検証失敗と保存失敗は入力の近くに短く出る
  - 進行中は再実行できない
  - _Requirements: 2.1, 2.2, 2.5, 7.2, 7.4_
  - _Boundary: LedgerForms_
  - _Depends: 5.2, 6.2_

- [x] 6.5 対象月を切り替えると要約と一覧がその月の発生日だけになる
  - 不正な月指定は当月に倒れる
  - 画面上で月を変えた結果が一覧より先の要約と一致する
  - _Requirements: 4.1, 4.2_
  - _Boundary: LedgerPage_
  - _Depends: 6.1, 6.2_

- [x] 6.6 自分の記録を直し、削除は確認後にだけ行う
  - 変更後の内容で記録が更新され一覧と要約が追従する
  - 確認しない削除では記録が残る
  - 他者の記録は見せず変更しない
  - _Requirements: 5.1, 5.2, 5.3, 5.4_
  - _Boundary: LedgerForms_
  - _Depends: 5.2, 6.3_

- [x] 7. 横断: 失敗表示とシェル
- [x] 7.1 取得または保存の失敗でも既存の家計表示を消さず失敗を示す
  - 利用者がデータを失ったように見えない
  - 認証失敗は認証画面の短文に留め家計を出さない
  - _Requirements: 6.3, 1.3, 1.8_
  - _Depends: 4.1, 6.4_

- [x] 7.2 全体シェルの題名と説明を家計簿向けにし認証操作を家計画面から使える
  - ログアウト操作が認証済み利用者に提供される
  - 認証状態の表示責任はページ側に残る
  - _Requirements: 1.4, 7.5_
  - _Depends: 3.4, 6.2_

- [x] 8. 検証
- [x] 8.1 変更系操作をモックして未ログイン・未確認削除・検証失敗を確認する
  - 未ログインでは家計が変わらない
  - 確認なし削除では記録が残る
  - 本番プロジェクトは叩かない
  - _Requirements: 1.5, 2.3, 5.3, 6.2_

- [x]* 8.2 ログインして支出を1件残し要約が更新され削除確認後に消える流れを確認する
  - 受け入れ基準のクリティカルパス（登録またはログイン、記録、要約、削除）を後回し可能な補助検証とする
  - _Requirements: 1.2, 2.1, 4.1, 5.2_
